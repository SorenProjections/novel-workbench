# 真实模型效果记录方案

此文档是后续评测的执行方案，目前没有填写真实模型实验结果。仓库已有的固定质量样例
检查机械规则和故事约束，不能据此宣称长篇生成质量提升。

## 对照方式

选用自己有权公开的固定创作任务，保存题目、人物设定、硬约束与目标篇幅。比较：

1. 同一模型直接生成。
2. 当前工作台完整流程，记录人工审核及修改次数。

两组记录相同的模型版本、采样配置、目标输出规模和预算规则。多次独立运行，保留失败案例；
预算不一致时，分别呈现质量和实际消耗，不能把额外模型调用或人工修改的收益都归因于编排策略。

## 每次记录

| 字段 | 内容 |
|---|---|
| 任务与版本 | 任务 ID、Git 提交、Prompt/StepSpec 版本、模型标识 |
| 输出与约束 | 目标篇幅、实际篇幅、预先定义的硬约束 |
| 一致性 | 人物/设定/时间线冲突数及对应文本锚点 |
| 人工投入 | 审核次数、修改次数、实际修改时间 |
| 消耗 | 输入/输出 token、重试次数、总耗时、按当时账单记录的费用 |
| 结果 | 通过、失败或人工终止，以及原因 |

建议采用隐藏组别的人工评阅；事先约定冲突定义和评分标准，保留原文证据。
如果增加上下文策略的消融，只改变被研究的策略，其余条件保持一致。
运行原始文件仍放在本地隔离目录，公开前另行整理有授权且不含敏感信息的样例。
