# novel-workbench 理解学习集合

这不是一套要求你先学完 Python、React 再回来看的课程，而是一套用当前项目反向学习的导航。

目标不是让你背代码，而是让你逐渐具备三种能力：

1. 能说清楚一次操作经过了哪些文件、数据发生了什么变化。
2. 能判断 AI 建议的修改是否合理，并知道怎样验证。
3. 能在作品集演示、团队交流和实习面试中诚实地讲清自己的贡献。

## 学习方法

每次只学习一个闭环，建议每天 45～90 分钟：

1. 先看课程里的流程图，不急着打开所有代码。
2. 按“必读代码”顺序阅读，每次只看指定函数附近。
3. 用自己的话完成课后记录，禁止直接复制课程原文。
4. 运行指定验证命令，观察真实输出。
5. 把不理解的问题写进 `学习记录.md`，下一次集中解决。

可以继续使用 AI，但每次让 AI 修改代码前必须先回答：

- 我认为问题发生在哪一层？
- 我预计要修改哪个文件？
- 修改成功后，什么测试或页面现象会发生变化？

## 路线

| 阶段 | 主题 | 学完后应该能做到 |
|---|---|---|
| 0 | 项目地图与术语 | 说出前端、API、编排器、模型、暂存区和权威层分别负责什么 |
| 1 | 点击生成后的完整链路 | 从按钮一路追到审核稿文件，并解释 SSE 进度 |
| 2 | 批准为何能解锁下一步 | 解释暂存、校验、提交、版本与下一步解锁 |
| 3 | DeepSeek 调用与失败 | 区分超时、重试、结构校验失败和缓存命中 |
| 4 | 前端状态与错误显示 | 能定位页面为何卡住、为何按钮不可点、错误从哪里显示 |
| 5 | 存储、测试与调试 | 能用测试复现问题，知道运行数据保存在哪里 |
| 6 | 公网化与安全边界 | 能解释为什么当前不能直接开放给陌生用户 |
| 7 | 作品集与技术讲解 | 完成 3 分钟演示和 15 分钟代码讲解 |

## 第一周安排

- 第 1 天：读项目地图，画一遍六层结构。
- 第 2 天：完成第一课第 1～3 节。
- 第 3 天：完成第一课代码追踪练习。
- 第 4 天：完成第二课，解释暂存与批准的区别。
- 第 5 天：运行相关测试，记录一个不理解的失败。
- 第 6 天：用 5 分钟给“完全不懂代码的人”讲解项目。
- 第 7 天：填写能力检查表，整理下一周问题。

## 基本原则

- 看不懂是正常结果，不是失败。
- 能找到代码位置，比能背语法更重要。
- 能提出正确的验证方法，比猜一个答案更重要。
- 不隐瞒 AI 辅助开发，但必须逐步取得对系统的解释权。
