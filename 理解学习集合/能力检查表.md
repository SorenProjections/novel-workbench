# 能力检查表

这不是考试成绩，而是决定下一步应该补什么。

## A. 五分钟产品讲解

- [ ] 我能解释项目解决的核心问题。
- [ ] 我能说出三个真正不同于普通聊天写作的设计。
- [ ] 我能诚实说明项目目前不能直接公开商用的原因。
- [ ] 我能区分自己做出的产品决策和 AI 生成的具体代码。

## B. 十五分钟技术讲解

- [ ] 我能从生成按钮追踪到 FastAPI 路由。
- [ ] 我能解释 Orchestrator 为什么决定下一步。
- [ ] 我能指出 DeepSeek API Key 在哪里读取。
- [ ] 我能解释 staging 与 auth 的区别。
- [ ] 我能说明一次批准如何写入新版本。
- [ ] 我能说明一个已知并发或安全风险。

## C. AI 辅助开发控制力

- [ ] AI 提议改动时，我会先要求它指出根因和验证方法。
- [ ] 我会查看 diff，而不是只看 AI 的完成说明。
- [ ] 我至少能读懂自己提交的关键函数。
- [ ] 我会运行相关测试。
- [ ] 修改失败时，我会保留错误信息和复现步骤。
- [ ] 我不会把 `.env`、API Key 或用户数据发送到公开位置。

## D. 实习或兼职准备

- [ ] 我有一页项目介绍。
- [ ] 我有 2～4 分钟演示视频。
- [ ] 我有稳定的演示项目。
- [ ] 我能完成一次不依赖临场 AI 的代码讲解。
- [ ] 我能说清楚希望申请的岗位类型。
- [ ] 我不会在没有明确条件时交出完整源码。

## 判断

- A 完成 3 项、B 完成 4 项：可以开始联系 AI 产品/工作流岗位。
- B 完成 5 项、C 完成 5 项：可以更有底气申请 AI 应用开发实习。
- 不必全部完成后才投递；没有完成的项目就是接下来的学习任务。
